# MAX Web Chat

Веб-чат для мессенджера **MAX** через [GREEN-API](https://green-api.com/v3/docs/): вход по данным инстанса, новый чат по номеру телефона, отправка и получение сообщений в реальном времени. Тестовое задание на позицию «Фронтенд-разработчик React».

## Попробовать

**Без аккаунта.** На экране входа нажмите «Демо-режим без GREEN-API». Через секунду придёт сообщение от нового контакта; создайте чат по любому номеру, напишите — статусы сменятся как в настоящем API, через пару секунд придёт ответ. Номер, оканчивающийся на `0000`, считается незарегистрированным в MAX, сообщение со словом «ошибка» не отправится.

**Со своим инстансом.** Введите `apiUrl`, `idInstance` и `apiTokenInstance` из личного кабинета, нажмите «+» и найдите собеседника по номеру (РФ или РБ). В настройках инстанса должны быть:
- включены уведомления о входящих, об отправленных через API и о статусах сообщений;
- **пустой `webhookUrl`** — иначе HTTP API не отдаёт уведомления (приложение подскажет, если это так).

## Что сделано

Сценарий задания: вход → новый чат по номеру → отправка через SendMessage → получение ответа через ReceiveNotification / DeleteNotification.

Сверх задания:
- статусы сообщений: часы → ✓ отправлено/доставлено → ✓✓ прочитано, ошибка с причиной;
- список чатов и история переживают перезагрузку страницы (журналы GREEN-API за сутки, история чата при открытии);
- имена контактов вместо номеров, счётчик непрочитанных, поиск по чатам и сообщениям;
- понятные ошибки входа и подключения: не привязан аккаунт, инстанс запускается, задан `webhookUrl`, неверный токен;
- визуальный язык веб-версии MAX, светлая и тёмная темы (по умолчанию — как в системе, переключатель в навигационной колонке), мобильная вёрстка.

## Запуск

Нужен Node.js 20.19+ или 22.12+.

```bash
npm install
npm run dev     # http://localhost:5173
npm test        # unit-тесты
npm run build   # проверка типов и сборка в dist/
```

## Ключевые решения

- **Чат создаётся по chatId из CheckAccount, а не по `номер@c.us`.** В MAX chatId — не номер телефона: при отправке «по номеру» ответы и статусы приходят с другим chatId и не попадают в открытый чат.
- **Последовательный long polling.** Цикл «получить → обработать → удалить» без параллельных запросов к одной FIFO-очереди; DeleteNotification вызывается даже при ошибке обработки, чтобы одно битое уведомление не заблокировало очередь. При сбоях — пауза 1 → 30 с.
- **Идемпотентное состояние.** Сообщения добавляются только upsert по id, статус только растёт. Повторная доставка, эхо собственного сообщения и статус, пришедший раньше ответа SendMessage, не создают дублей и не откатывают статус. Логика — чистые функции с unit-тестами.
- **zod на границе с сетью.** Незнакомое или битое уведомление не роняет приложение, а просто подтверждается и пропускается.
- **Порты и адаптеры.** UI и состояние зависят от интерфейса `MessengerGateway`, а не от GREEN-API; реализация выбирается в одном месте (`app/composition.ts`). Демо-режим — это просто вторая реализация шлюза, поэтому в нём работают те же ветки кода, что и с настоящим API.

Стек: React 19, TypeScript (strict), zustand, zod, Vite, vitest. UI-библиотек нет.

## Ограничения

- **Токен инстанса хранится в браузере** (sessionStorage, до закрытия вкладки) и виден в запросах — так устроен формат URL GREEN-API. Для продакшена нужен бэкенд-прокси, который держит токен на сервере; в коде для этого меняется только `HttpClient`.
- **Несколько вкладок делят одну очередь уведомлений** — каждое уведомление получит только одна из них.
- **Только текст.** Фото, стикеры и другие типы показываются заглушкой.
- **Глубина истории:** список чатов — за последние сутки, в чате — последние 100 сообщений.
- **Номера только РФ (+7) и РБ (+375)** — ограничение CheckAccount.

## Тесты

`npm test` — 124 теста: гонки эха и статусов, повторная доставка, цикл опроса с ошибками и отменой, разбор уведомлений и журналов на примерах из документации, перевод HTTP-ошибок, нормализация номеров.
